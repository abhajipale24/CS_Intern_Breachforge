# OWASP Top 10 — Category Review

## A01 — Broken Access Control

Broken Access Control occurs when an application does not properly restrict what users are allowed to access or do. A user may be able to access resources or functions that should be restricted.

## A02 — Security Misconfiguration

Security Misconfiguration happens when security settings are incorrectly configured or unnecessary features, services, or default settings are left enabled. Proper configuration helps reduce the application's attack surface.

## A03 — Software Supply Chain Failures

Software Supply Chain Failures can occur when an application depends on insecure or compromised third-party software, libraries, packages, or development components. These dependencies can introduce security risks into the application.

## A04 — Cryptographic Failures

Cryptographic Failures happen when sensitive information is not properly protected using appropriate cryptography. This can include weak protection or transmitting sensitive data without adequate encryption.

## A05 — Injection

Injection occurs when untrusted user input is incorrectly processed as part of a command or query. Examples include SQL injection and command injection.

## A06 — Insecure Design

Insecure Design occurs when security weaknesses are built into the application's design or business logic. Security requirements and protections should be considered while designing the application.

## A07 — Authentication Failures

Authentication Failures occur when an application does not properly verify the identity of users or securely manage authentication and sessions. Weak authentication controls can allow unauthorized account access.

## A08 — Software or Data Integrity Failures

Software or Data Integrity Failures occur when software, updates, dependencies, or important data are not properly protected from unauthorized or untrusted changes. This can affect the integrity and security of the application.

## A09 — Security Logging & Alerting Failures

Security Logging & Alerting Failures happen when important security events are not properly recorded, monitored, or alerted on. This can make suspicious activity difficult to detect and investigate.

## A10 — Mishandling of Exceptional Conditions

Mishandling of Exceptional Conditions occurs when an application handles unexpected errors, failures, or unusual situations insecurely. Poor error handling can cause unexpected behavior or expose sensitive information.

# Summary

The OWASP Top 10 categories help identify common security risks in web applications. They provide a useful checklist for understanding where security weaknesses may exist and how applications can be designed and configured more securely.
